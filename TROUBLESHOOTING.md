## Проблемы с GitHub Actions

### ❌ Workflow не запускается автоматически

**Симптомы:**
- Прошло больше 6 часов, но автоматического запуска не было
- В Actions нет новых запусков по расписанию

**Причины и решения:**

1. **Actions отключены для репозитория**
   ```
   Settings → Actions → General → Actions permissions
   ✅ Выберите "Allow all actions and reusable workflows"
   ```

2. **Репозиторий заархивирован**
   ```
   Settings → General → Danger Zone
   Убедитесь, что репозиторий не archived
   ```

3. **Репозиторий приватный и аккаунт Free**
   ```
   Приватные репозитории на Free плане имеют лимит 2000 минут/месяц
   Проверьте: Settings → Billing & plans → Usage this month
   ```

4. **Первый запуск еще не был выполнен**
   ```
   Cron не запустится автоматически до первого ручного запуска
   Actions → Auto Update Happ Subscription → Run workflow
   ```

**Проверка:**
```bash
# Убедитесь, что .github/workflows/update.yml существует
ls -la .github/workflows/
```

### ❌ Ошибка "GIST_TOKEN not set"

**Симптомы:**
```
❌ ОШИБКА: Не установлена переменная окружения GIST_TOKEN
```

**Решения:**

1. **Проверьте наличие секрета**
   ```
   Settings → Secrets and variables → Actions
   Должен быть секрет с именем GIST_TOKEN (ЗАГЛАВНЫМИ!)
   ```

2. **Проверьте написание**
   ```
   Точное имя: GIST_TOKEN (не gist_token, не GistToken)
   ```

3. **Пересоздайте токен**
   ```
   GitHub → Settings → Developer settings → Personal access tokens
   Generate new token (classic)
   Права: ✅ gist
   Срок: No expiration
   Скопируйте и добавьте в Secrets
   ```

---

### ❌ Ошибка "403 Forbidden" или "401 Unauthorized"

**Симптомы:**
```
❌ Ошибка обновления Gist: 403 Client Error: Forbidden
```

**Причины:**

1. **Токен просрочен**
   - Проверьте дату истечения токена
   - Создайте новый токен и обновите GIST_TOKEN

2. **Недостаточно прав**
   - Токен должен иметь права `gist`
   - Пересоздайте токен с нужными правами

3. **Токен удален**
   - Проверьте список токенов в настройках GitHub
   - Создайте новый, если старый отсутствует

**Решение:**
```
1. GitHub → Settings → Developer settings → Personal access tokens
2. Удалите старый токен (если есть)
3. Generate new token (classic)
4. Скопируйте токен
5. Репозиторий → Settings → Secrets → GIST_TOKEN → Update
```

```
Error: Resource not accessible by integration
```

**Решение:**

Settings → Actions → General → Workflow permissions
✅ Read and write permissions

## Проблемы с GitHub Gist

### ❌ Gist не обновляется

**Симптомы:**
- Workflow проходит успешно, но Gist содержит старые данные
- В логах нет ошибок

**Решение:**

1. **Проверьте GIST_ID**
   ```
   Откройте логи последнего успешного запуска
   Найдите строку: "Обновление Gist <ID>"
   Убедитесь, что это правильный ID
   ```

2. **Проверьте Gist вручную**
   ```
   https://gist.github.com/ваш-username/GIST_ID
   Откройте и проверьте содержимое
   ```

3. **Очистите кэш браузера**
   ```
   Gist может быть закэширован браузером
   Ctrl+Shift+R (hard refresh)
   ```

---

### ❌ Создается новый Gist при каждом запуске

**Симптомы:**
- У вас накапливаются десятки Gist'ов
- В логах: "Создание нового Gist..."

**Причина:**
- GIST_ID не установлен в Secrets

**Решение:**
```
1. Откройте логи ПЕРВОГО успешного запуска
2. Найдите: "GIST_ID: a1b2c3d4e5f6..."
3. Скопируйте ID
4. Settings → Secrets and variables → Actions
5. New repository secret:
   Name: GIST_ID
   Value: <ваш ID>
6. Add secret
```

---

### ❌ Ошибка "Gist not found" (404)

**Симптомы:**
```
❌ Ошибка обновления Gist: 404 Client Error: Not Found
```

**Причины:**

1. **Неправильный GIST_ID**
   - Проверьте ID в Secrets
   - Убедитесь, что Gist существует: https://gist.github.com/username/GIST_ID

2. **Gist удален**
   - Gist был удален вручную
   - Удалите GIST_ID из Secrets, чтобы создать новый

3. **Gist принадлежит другому аккаунту**
   - Токен не имеет доступа к Gist другого пользователя

**Решение:**
```
Вариант 1: Удалить GIST_ID
Settings → Secrets → GIST_ID → Remove
При следующем запуске создастся новый Gist

Вариант 2: Создать Gist вручную
1. https://gist.github.com → New gist
2. Filename: subscription.txt
3. Content: initial
4. Create secret gist
5. Скопируйте ID из URL
6. Добавьте в Secrets как GIST_ID
```

## Проблемы с Happ API

### ❌ Ошибка "API не вернул happ:// ссылку"

**Симптомы:**
```
⚠️ Неожиданный формат ответа: {"error": "..."}
ValueError: API не вернул happ:// ссылку
```

**Причины:**

1. **API перегружен**
   - Слишком много запросов
   - Временная недоступность

2. **Некорректный URL подписки**
   - Gist URL недоступен публично
   - URL содержит ошибки

3. **Изменился формат API**
   - API обновился
   - Требуется обновление скрипта

**Решение:**

1. **Подождите и попробуйте снова**
   ```
   Actions → Auto Update → Run workflow
   Подождите 10-15 минут перед повторной попыткой
   ```

2. **Проверьте URL Gist вручную**
   ```
   Откройте в браузере RAW URL из логов
   Должен открываться Base64 текст
   Если 404 - проблема с Gist, не с API
   ```

3. **Проверьте API вручную**
   ```bash
   curl -X POST https://crypto.happ.su/api-v2.php \
     -H "Content-Type: application/json" \
     -d '{"url": "YOUR_GIST_RAW_URL"}'
   ```

---

### ❌ Timeout при обращении к Happ API

**Симптомы:**
```
requests.exceptions.Timeout: HTTPSConnectionPool...
```

**Причины:**
- API недоступен
- Сетевые проблемы GitHub Actions

**Решение:**
```
Это временная проблема.
1. Подождите 30-60 минут
2. Запустите workflow повторно
3. Если проблема повторяется > 24ч - проверьте статус API
```

## Проблемы с источниками прокси

### ❌ "Не удалось получить ни одного валидного сервера"

**Симптомы:**
```
❌ ОШИБКА: Не удалось получить ни одного валидного сервера
```

**Причины:**

1. **Все источники временно недоступны**
   - GitHub репозитории недоступны
   - Сетевые проблемы

2. **Источники изменили структуру**
   - Переехали на другой URL
   - Изменили формат данных

3. **GitHub Rate Limit**
   - Превышен лимит запросов к GitHub API
   - Обычно сбрасывается через час

**Решение:**

1. **Проверьте источники вручную**
   ```
   Откройте каждый URL из PROXY_SOURCES в браузере
   Если 404/403 - источник мертв, удалите его из main.py
   ```

2. **Добавьте новые источники**
   ```python
   # Отредактируйте main.py
   PROXY_SOURCES = [
       "https://raw.githubusercontent.com/...",  # Ваш новый источник
       # ... остальные
   ]
   ```

3. **Подождите и повторите**
   ```
   Обычно источники восстанавливаются в течение 1-6 часов
   GitHub Actions автоматически попробует снова через 6 часов
   ```

---

### ⚠️ "Получено 0 серверов" из конкретного источника

**Симптомы:**
```
📥 Загрузка из: https://...
   ✅ Получено 0 серверов
```

**Это нормально**, если:
- Хотя бы один источник возвращает серверы
- Общее количество > 0

**Действия:**
```
Ничего делать не нужно.
Система автоматически использует работающие источники.
```

**Если проблема со ВСЕМИ источниками:**
```
1. Проверьте подключение к интернету на GitHub Actions
2. Проверьте, что репозитории-источники существуют
3. Добавьте альтернативные источники
```

## Проблемы с приложением Happ

### ❌ "Подписка не найдена" или "Invalid subscription"

**Симптомы:**
- Приложение не может импортировать ссылку
- Ошибка при добавлении подписки

**Причины:**

1. **Неправильно скопирована ссылка**
   - Ссылка обрезана
   - Добавлены лишние символы

2. **Happ:// ссылка устарела**
   - API сгенерировал битую ссылку
   - Нужна регенерация

**Решение:**

1. **Проверьте ссылку**
   ```
   Ссылка должна начинаться с: happ://crypt5/
   Длина обычно 30-50 символов после crypt5/
   Не должно быть пробелов или переносов строк
   ```

2. **Скопируйте заново**
   ```
   Откройте HAPP_LINK.txt в репозитории
   Выделите всю ссылку целиком
   Copy → Paste в Happ
   ```

3. **Регенерируйте ссылку**
   ```
   Actions → Auto Update → Run workflow
   Получите новую happ:// ссылку
   ```

---

### ❌ Серверы не обновляются в приложении

**Симптомы:**
- В Happ всё еще старые серверы
- Обновление подписки не помогает

**Причины:**

1. **Приложение кэширует подписку**
   - Happ не запрашивает обновления автоматически

2. **Gist действительно не обновлен**
   - Workflow не запускался
   - Или завершился с ошибкой

**Решение:**

1. **Принудительное обновление в Happ**
   ```
   Откройте Happ
   Subscriptions → Ваша подписка
   Нажмите кнопку обновления (↻)
   Подождите 10-30 секунд
   ```

2. **Удалите и добавьте подписку заново**
   ```
   Удалите подписку из Happ
   Добавьте ссылку happ:// заново
   Проверьте список серверов
   ```

3. **Проверьте Gist**
   ```
   Откройте Gist RAW URL в браузере
   Скопируйте Base64 содержимое
   Декодируйте на https://www.base64decode.org/
   Убедитесь, что серверы свежие
   ```

---

### ❌ Все серверы мертвые / не подключаются

**Симптомы:**
- Ни один сервер из подписки не работает
- Таймауты при подключении

**Причины:**

1. **Публичные прокси быстро блокируются**
   - Это нормально для бесплатных источников
   - Серверы живут 1-24 часа

2. **Проблемы с интернетом на вашей стороне**
   - DPI блокирует подключения
   - Нужен другой протокол

3. **Серверы действительно старые**
   - Workflow давно не запускался

**Решение:**

1. **Попробуйте другой протокол**
   ```
   В Happ фильтруйте серверы:
   - Только VLESS
   - Только Trojan
   - Только Shadowsocks
   ```

2. **Дождитесь обновления**
   ```
   Workflow обновит серверы в течение 6 часов
   Или запустите вручную: Actions → Run workflow
   ```

3. **Проверьте последнее обновление**
   ```
   Откройте README.md в репозитории
   Найдите "Последнее обновление: ..."
   Если > 12 часов назад - проверьте Actions
   ```

## Общие ошибки

### ❌ Python ошибки в логах

**ModuleNotFoundError: No module named 'requests'**
```
Решение: Проверьте requirements.txt
В workflow должен быть шаг: pip install -r requirements.txt
```

**SyntaxError: invalid syntax**
```
Решение: Проверьте версию Python
В workflow должно быть: python-version: '3.11'
Пересоздайте main.py из оригинала
```

**UnicodeDecodeError**
```
Решение: Один из источников вернул битые данные
Это обрабатывается автоматически
Если ошибка повторяется - удалите проблемный источник
```

---

### ❌ Git ошибки при коммите

**Ошибка: "refusing to allow a GitHub App to create or update workflow"**
```
Решение:
Settings → Actions → General → Workflow permissions
✅ Allow GitHub Actions to create and approve pull requests
```

**Ошибка: "Updates were rejected because the remote contains work"**
```
Решение:
В workflow добавить перед git push:
git pull --rebase origin main
```

### ❌ Workflow долго выполняется (> 5 минут)

**Причины:**
- Источники медленно отвечают
- Таймауты на сетевых запросах

**Решение:**
```
Это нормально, если в итоге завершается успешно.
Если workflow висит > 10 минут:
1. Cancel workflow
2. Проверьте логи - где застряло
3. Уменьшите REQUEST_TIMEOUT в main.py (с 30 до 15)
```

## 🆘 Когда ничего не помогает

### Полный сброс системы

1. **Удалите все секреты**
   ```
   Settings → Secrets and variables → Actions
   Удалите GIST_TOKEN и GIST_ID
   ```

2. **Удалите старые Gist'ы**
   ```
   https://gist.github.com
   Найдите все Gist'ы subscription.txt
   Удалите их
   ```

3. **Создайте новый токен**
   ```
   GitHub → Settings → Developer settings
   Personal access tokens → Generate new token (classic)
   Права: ✅ gist
   Скопируйте токен
   ```

4. **Добавьте новый GIST_TOKEN**
   ```
   Репозиторий → Settings → Secrets
   New secret: GIST_TOKEN
   Value: новый токен
   ```

5. **Запустите workflow**
   ```
   Actions → Auto Update → Run workflow
   ```

6. **Сохраните новый GIST_ID**
   ```
   Откройте логи → найдите GIST_ID
   Settings → Secrets → New secret: GIST_ID
   ```

7. **Получите новую happ:// ссылку**
   ```
   Откройте HAPP_LINK.txt
   Скопируйте и добавьте в Happ заново
   ```

## 📋 Как внести вклад

### 1. Сообщить об ошибке (Bug Report)

Если вы нашли баг:

1. Проверьте, что проблема еще не решена в [Issues](../../issues)
2. Создайте новый Issue с меткой `bug`
3. Опишите проблему:
   - Шаги для воспроизведения
   - Ожидаемое поведение
   - Фактическое поведение
   - Логи из GitHub Actions (если применимо)
   - Скриншоты (если помогут)

### 2. Предложить улучшение (Feature Request)

Если у вас есть идея:

1. Создайте Issue с меткой `enhancement`
2. Опишите:
   - Какую проблему решает ваше предложение
   - Как это должно работать
   - Альтернативные решения, которые вы рассматривали

### 3. Добавить код (Pull Request)

1. **Fork репозитория**
   ```bash
   # Нажмите Fork на GitHub
   git clone https://github.com/ваш-username/happ-auto-proxy.git
   cd happ-auto-proxy
   ```

2. **Создайте ветку для изменений**
   ```bash
   git checkout -b feature/ваше-улучшение
   # или
   git checkout -b fix/название-бага
   ```

3. **Внесите изменения**
   - Следуйте стилю кода проекта
   - Добавьте комментарии для сложной логики
   - Обновите документацию при необходимости

4. **Протестируйте локально**
   ```bash
   python test_local.py
   ```

5. **Закоммитьте изменения**
   ```bash
   git add .
   git commit -m "feat: описание вашего изменения"
   # или
   git commit -m "fix: описание исправления"
   ```

   **Формат коммитов:**
   - `feat:` - новый функционал
   - `fix:` - исправление бага
   - `docs:` - изменения в документации
   - `style:` - форматирование, отступы
   - `refactor:` - рефакторинг кода
   - `test:` - добавление тестов
   - `chore:` - обновление зависимостей, конфигурации

6. **Push изменений**
   ```bash
   git push origin feature/ваше-улучшение
   ```

7. **Создайте Pull Request**
   - Перейдите в оригинальный репозиторий на GitHub
   - Нажмите "Compare & pull request"
   - Опишите что изменили и зачем
   - Ссылка на связанные Issues (если есть)

## 🧪 Тестирование

Перед отправкой PR:

1. **Локальный тест**
   ```bash
   python test_local.py
   ```

2. **Ручная проверка workflow**
   - Запустите workflow в своем fork
   - Убедитесь, что нет ошибок
   - Проверьте, что happ:// ссылка генерируется

3. **Проверка документации**
   - Все ссылки работают
   - Скриншоты актуальны
   - Нет опечаток
